# ZOS 0.1.0 alpha

Экспериментальный форк предоставленного MineOS для **Minecraft / OpenComputers**.
Это Lua-система для игрового компьютера, не загрузочный ISO, не Linux и не ОС для ПК.
ZOS EFI — Lua-прошивка EEPROM; к стандарту UEFI отношения не имеет.

## Что реализовано

- Оболочка на исходном оконном движке MineOS: верхняя панель меню приложений,
  нижняя синяя панель, зелёная кнопка «Пуск», часы и кнопки открытых окон.
- Сворачивание/восстановление окон. «Пуск → Все окна» позволяет восстановить окно,
  даже если его кнопка не поместилась на панели. «Все программы» читает .app-каталоги.
- Светлая тема ZOS Luna и синие заголовки стандартных titledWindow-окон.
  Отдельные приложения со своим оформлением не перекрашиваются принудительно.
- Чёрный загрузочный экран с тремя синими движущимися символами-блоками в духе XP.
  Блоки сдвигаются между реальными этапами загрузки, без искусственных задержек.
- Статичные процедурные обои ZOS Hills и ZOS Teal; это не оригинальная картинка Bliss.
- Установщик в синем текстовом стиле XP Setup: RU/EN интерфейс, выбор языка системы,
  выбранные/все языковые пакеты, обои, имя пользователя, Lite/Full и целевой HDD.
- ZOS EFI: выбор диска по F2, безопасная загрузка по F8, сообщения об ошибках,
  чтение /OS.lua или /init.lua. Без форматирования и без загрузки кода из интернета.
- Исходный MineOS App Market и отдельный ZOS Packages для локальных .zpk-пакетов.
- Все 29 исходных файлов библиотек присутствуют; 28 из них побайтно не изменены.
  System.lua изменён точечно, имена публичных API и пути сохранены. Добавлены 2 библиотеки ZOS.

**Это alpha, а не подтверждённый в игре стабильный релиз.** Автоматические проверки
на Lua 5.3 и имитации компонентов пройдены. Рендеринг на реальном GPU OpenComputers,
все приложения и работа внешнего App Market в Minecraft не проверялись.

## Требования

- OpenComputers с Lua 5.2/5.3 и установленная OpenOS для запуска установщика.
- Tier 3 GPU и экран, доступное разрешение не ниже 80×25.
- Не менее 2 MiB RAM; больше для тяжёлых приложений.
- Отдельный **пустой** целевой HDD. Рекомендуется Tier 3 / от 4 MiB.
- Исходный диск с OpenOS и распакованной сборкой: рекомендуется от 4 MiB свободного
  общего объёма с учётом OpenOS; сам каталог system занимает примерно 2.5 MB.
  Исходный диск должен быть доступен для записи второй резервной копии EEPROM.
- EEPROM; для ZOS EFI требуется 2837 байт кода, стандартные 4096 байт подходят.
- Internet Card нужна только для сетевой установки и App Market; офлайн-установка
  распакованного дистрибутива не требует интернета.

## Офлайн-установка — доступна сразу

1. Сделайте резервную копию мира. Выключите игровой компьютер; перед изменением
   файлов дисков вне игры закройте мир/остановите сервер.
2. Распакуйте ZIP на настоящем компьютере. Скопируйте **каталог ZOS-0.1.0 целиком**
   на исходный игровой диск с OpenOS, не заменяя его существующие файлы.
   Обычно файлы дисков хранятся в `saves/<мир>/opencomputers/<UUID-диска>/`;
   точный путь зависит от сервера/сборки. Если прямого доступа к миру нет,
   понадобится файловый перенос средствами вашей сборки либо публикация по HTTPS.
3. Подключите отдельный пустой HDD, загрузите OpenOS. При копировании в корень диска:

```sh
/ZOS-0.1.0/Installer/install.lua /ZOS-0.1.0
```

Если каталог находится на другом смонтированном диске, замените **оба пути**
на реальные абсолютные пути. Например, `/mnt/abc/ZOS-0.1.0/...`.
4. Выберите язык, языковые пакеты, обои, Lite/Full и имя пользователя.
   На первом экране лицензии сначала выйдите и прочитайте `NOTICE.md` и `system/LICENSE`.
5. Выберите пустой целевой диск и подтвердите копирование. Установщик никогда
   не предлагает диск-источник, временный диск или непустой диск и не форматирует их.
6. После успешного копирования отдельно подтвердите прошивку **ZOS EFI**.
   Её резервные копии уже записаны: на целевом диске `/ZOS/Backup/` и в каталоге
   `EEPROM-backup-<адрес>` внутри исходного дистрибутива. Сохранены код, метка и boot data.
7. Выполните `reboot` в OpenOS. При прошивке ZOS EFI boot data уже указывает на ZOS HDD.
   Если оставили старую прошивку, **автоматическое переключение не выполняется**:
   выберите ZOS HDD средствами текущей EFI. Файл /init.lua добавлен для совместимости
   со стандартной прошивкой OpenComputers.

Изначально пользователь создаётся **без пароля**. Настройте его в Settings → Users.
Начальное имя допускает латиницу, цифры, `_` и `-`; по Enter используется Guest.

## Lite и Full

Lite устанавливает все библиотеки и основные приложения: Finder, Settings, Console,
App Market, MineCode IDE, Picture View, Picture Edit, ZOS Packages. Большие игры,
3D-приложения и большинство анимированных обоев остаются только в дистрибутиве.
Full устанавливает все приложения и обои предоставленного архива.
Выбор языковых пакетов применяется в обоих режимах: выбранный язык + English либо все.
RU и EN поддерживаются в новой оболочке и установщике; для других языков новая оболочка
использует английский, тогда как стандартные приложения используют пакеты MineOS.

## Оптимизация без обещаний выдуманных цифр

- Прозрачность и размытие по умолчанию отключены.
- Статичные фоны не создают собственных анимационных обработчиков.
- Периодическая перерисовка рабочего стола для статичных обоев — раз в секунду,
  вместо интервала 0.01 s в исходном пути анимированных обоев; события обрабатываются отдельно.
- Основной цикл ожидает события до 0.05 s, вместо постоянного опроса с timeout=0.
  Движок активных анимаций сохраняет своё штатное поведение.
- Lite сокращает занятую диском площадь, но не меняет API библиотек.

**Измерений FPS, времени загрузки и RAM в игре пока нет.** Унаследованный GUI,
буферы экрана и обязательные библиотеки всё ещё требуют сопоставимой с MineOS памяти.
Полная совместимость всех сторонних программ не гарантируется; особенно это касается
программ, обращающихся к внутренним объектам дока или заменяющих OS.lua/System.lua.

## Приложения

### MineOS App Market

Открывается из Пуска. Требует Internet Card и доступного стороннего API.
Адреса API сохранены из архива; их работоспособность не проверялась.
**Не обновляйте всю MineOS поверх ZOS**: это может заменить оболочку и System.lua.
Нет проверки подписей сторонних приложений; устанавливайте только доверенный код.

### Локальные .zpk

Пример: `examples/Hello.zpk`. Перенесите его на доступный ZOS диск, откройте
«Пуск → Установка приложений», введите полный путь, нажмите «Установить .zpk».
Приложение появится в «Пуск → Все программы» после открытия меню заново.

Создание пакета на обычном компьютере:

```sh
python3 tools/make_zpk.py /путь/Hello.app /путь/Hello.zpk
```

Формат ZPK1 описан в `docs/ZPK1.md`. Это простой локальный формат, не формат
публикаций App Market. Установка запрещает абсолютные пути, `..`, дубликаты,
подмену уже существующего .app, выход за каталог приложения и обрезанные данные.
Приложения при установке **не запускаются**. Их код всё равно может быть опасным
после запуска: ZPK1 не предоставляет песочницу, подписи или аудит безопасности.
Неудачные staging-каталоги `.zos-<имя>.stage` оставляются для ручной проверки.

## Pastebin — скрипт готов, публикации ещё нет

`Installer/pastebin.lua` — короткий загрузочный скрипт, а не сам дистрибутив.
Pastebin ID в этой сборке **не создан**, публичный репозиторий тоже не опубликован.

Чтобы получить рабочую команду:

1. После проверки лицензии разместите содержимое `ZOS-0.1.0/` на доверенном HTTPS-хосте
   с прямым доступом к файлам. Сохраните пути и регистр. Например, корень GitHub raw
   может выглядеть как `https://raw.githubusercontent.com/USER/REPO/main/`.
2. Разместите **содержимое `Installer/pastebin.lua`** на Pastebin и получите настоящий ID.
3. В OpenOS выполните, заменив **оба** заполнителя:

```sh
pastebin run YOUR_ID https://HOST/ZOS-0.1.0/
```

Этот шаблон **не работает без реального ID и хостинга**. Не используйте ID старого MineOS:
он устанавливает другой продукт. Можно обойтись без Pastebin: скачать bootstrap через
wget с вашего хоста и запустить его с URL корня дистрибутива первым аргументом.

Загрузчик сохраняет полную сборку в `/home/ZOS-download/`, а не в маленький `/tmp`.
Целевой диск должен быть отдельным и пустым. Если загрузка прервана, осмотрите/переименуйте
`/home/ZOS-download/` перед повтором. HTTPS-хост, manifest и installer должны быть
доверенными: Adler-32 обнаруживает повреждения копии, но не защищает от подмены сервера.

## Восстановление

- F2 в первые 1.2 s после включения — выбор загрузочного диска.
- F8 — безопасная загрузка: без обоев, пользовательских автозадач и включения сети
  через стандартный updateUser-путь. Это не отдельная rescue-ОС.
- При неудачном копировании EFI ещё не прошивается; промежуточные файлы остаются
  на целевом HDD в `/.zos-staging/`. Установщик не удаляет их автоматически.
- После частичного commit на целевом диске могут быть отдельные системные каталоги.
  OS.lua переносится последним. Возьмите новый пустой диск либо очистите только
  неудачную установку вручную после проверки содержимого.
- При ошибке прошивки выполняется попытка вернуть код, boot data и метку EEPROM.
  При аппаратной/постоянной ошибке восстановления это придётся сделать вручную.
- Для ручного возврата старой EFI используйте `docs/RECOVERY.md` и исходный OpenOS.

## Проверки и разработка

`tests/TEST-REPORT.txt` — фактический вывод тестов этой сборки.
На Linux с Python 3 и liblua 5.3:

```sh
python3 tools/build_manifest.py
python3 tests/run_tests.py
sha256sum -c SHA256SUMS
```

Проверяются синтаксис Lua и языковых ресурсов, целостность файлов, Lite/Full,
все библиотеки, фильтрация языков, сохранность существующего диска, резервирование
и откат EEPROM при искусственном сбое, F2/F8, установка пакетов и действия панели.
Реальный Minecraft/OpenComputers в эти проверки **не входит**.

Список изменений: `CHANGELOG.md`. Условия исходников: `NOTICE.md` и `system/LICENSE`.
